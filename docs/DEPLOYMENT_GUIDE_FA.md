# راهنمای بررسی و انتشار سایت ولوم هاوس

این نسخه برای بررسی آماده است، اما پیش از انتشار نهایی باید ظاهر و رزرو واقعی را آزمایش کنید. بک‌اند و آدرس فعلی Google Apps Script تغییر نکرده‌اند. به داده‌های قبلی دست نزنید.

## ۱. نسخه پشتیبان و باز کردن فایل
از مخزن GitHub نسخه پشتیبان (Code > Download ZIP) بگیرید. فایل Vellum-House-Revised.zip را Extract کنید. فایل index.html و CNAME باید در ریشه پوشه استخراج‌شده باشند، نه در زیرپوشه دیگری.

## ۲. نصب فونت‌های نهایی (پیش از انتشار توصیه می‌شود)
فونت‌های انتخابی Cormorant Garamond، Inter و Dana در فایل اولیه وجود نداشتند. در نسخه فعلی Georgia، DM Sans و Vazirmatn به عنوان جایگزین محلی استفاده می‌شوند. فونت دانا تجاری است؛ فایل WOFF2 متغیر و مجوز معتبر برای دامنه vhouse.ir را از عرضه‌کننده رسمی تهیه کنید.

اگر Python روی ویندوز نصب است، در پوشه اصلی سایت در نوار آدرس File Explorer عبارت `cmd` را تایپ کنید و Enter بزنید. سپس:

```
py tools/install_fonts.py
```

این دستور فونت‌های انگلیسی آزاد را از منبع رسمی Google Fonts دانلود می‌کند، فایل‌های محلی و مجوزها را ذخیره کرده و CSS را تنظیم می‌کند. برای نصب دانا (مسیر واقعی فایل خودتان را جایگزین کنید):

```
py tools/install_fonts.py --dana-only --dana "C:\Users\YourName\Downloads\Dana-Variable.woff2"
```

فقط فایل متغیر دارای وزن‌های لازم و مجوز وب را استفاده کنید؛ اگر فایل‌های وزن ثابت دارید، باید برای هر وزن @font-face جداگانه در assets/royal-fonts.css تعریف شود. مجوز دانا را مطابق شرایط عرضه‌کننده نگه دارید و مطمئن شوید انتشار فایل فونت در مخزن عمومی با شرایط آن سازگار است. اگر اجرای Python یا دسترسی اینترنت ممکن نیست، از Google Fonts نسخه‌های WOFF2 رسمی را تهیه و CSS را طبق مشخصات DESIGN.md تنظیم کنید. در DevTools مرورگر بررسی کنید فونت واقعی (نه جایگزین) نمایش داده می‌شود.

## ۳. پیش‌نمایش روی کامپیوتر
در همان پنجره CMD دستور زیر را اجرا کنید:

```
py -m http.server 8765
```

در Chrome باز کنید: http://localhost:8765/ و http://localhost:8765/en.html . سرور را با Ctrl+C متوقف کنید. روی فایل HTML مستقیماً دوبار کلیک نکنید؛ ماژول‌های رزرو ممکن است در file:// کار نکنند. هنگام بررسی ظاهری، فرم واقعی ارسال نکنید. در گوشی و مرورگرهای دیگر هم تست کنید. به دلیل محدودیت محیط ساخت، اسکرین‌شات مرورگر و تأیید بصری نهایی در این بسته انجام نشده است.

## ۴. انتشار در GitHub (پس از تأیید خودتان)
در مخزن فعلی، ابتدا یک شاخه review یا backup ایجاد کنید. در شاخه انتشار (معمولاً main)، Add file > Upload files را انتخاب کنید و محتوای پوشه استخراج‌شده را در همان مسیر قبلی قرار دهید. خود فایل ZIP را آپلود نکنید. CNAME با محتوای vhouse.ir و index.html باید در ریشه باقی بمانند. اگر تعداد فایل‌ها زیاد است، از GitHub Desktop برای جایگزینی فایل‌ها و Commit استفاده کنید. نام فایل‌های ویدئوی قبلی و CSS قدیمی در CHANGELOG آمده؛ فایل‌های بلااستفاده را فقط پس از تأیید نسخه جدید حذف کنید.

در Settings > Pages منبع انتشار قبلی و دامنه سفارشی را حفظ کنید. در Actions وضعیت انتشار را بررسی کنید؛ پس از موفقیت، vhouse.ir را باز و Ctrl+F5 بزنید. تنظیم DNS را تغییر ندهید مگر دامنه قبلاً به Pages وصل نباشد.

## ۵. بک‌اند و رزرو
هیچ فایل بک‌اند یا endpoint تغییر نکرده است؛ اگر قبلاً کار می‌کرد، نیازی به انتشار مجدد Apps Script نیست. به Google Sheets، Script Properties، Calendar و تریگرهای فعلی دست نزنید. اگر قبلاً تنظیم نشده است، README.md و راهنمای قبلی docs/START_HERE_FA.md را برای راه‌اندازی اولیه مطالعه کنید. با یک درخواست آزمایشی مجاز، ثبت اطلاعات، تقویم، عدم رزرو هم‌زمان، Google Meet و ایمیل تأیید را بررسی کنید. هیچ کلید خصوصی را در مخزن عمومی قرار ندهید. بعد از تست، رکورد آزمایشی را طبق سیاست تیم مدیریت کنید.

## ۶. در صورت اشکال
اگر نتیجه ظاهری یا رزرو رضایت‌بخش نبود، انتشار را متوقف کنید یا از ROLLBACK_GUIDE.md استفاده کنید. گزارش‌های TEST_REPORT.md و PERFORMANCE_REPORT.md محدودیت‌های تأیید این نسخه را مشخص می‌کنند.

## ۶. بررسی تغییرات نسخه جدید
ویدئوی دسکتاپ بدون تغییر و ویدئوی عمودی جدید برای موبایل استفاده می‌شود. ویدئوها به‌صورت پس‌زمینه نمایش داده می‌شوند؛ در برخی نسبت‌های تصویر ممکن است اندکی از لبه‌ها برش بخورد. صفحه درباره ما باید هر دو تصویر را کنار هم نشان دهد؛ با لمس تصویر یا قرار دادن نشانگر روی آن توضیحات نمایش داده می‌شوند. هر شش نقطه مسیر را انتخاب کنید و محل پایان خط را بررسی کنید. صفحات اصلی را در ابعاد واقعی گوشی و رایانه ببینید. اسکرول داخلی در فرم، تقویم و توضیحات بنیان‌گذاران مجاز است. در نمایشگر بسیار کوچک یا هنگام بزرگ‌نمایی متن نیز اسکرول داخلی برای جلوگیری از حذف محتوا در دسترس است. پس از تأیید، فایل‌های استخراج‌شده را جایگزین کنید. فایل قدیمی assets/media/hero-mobile.c4f6743aa437.mp4 دیگر استفاده نمی‌شود و پس از بررسی می‌توان آن را حذف کرد. فونت‌های نهایی هنوز به نصب نیاز دارند. بک‌اند را مجدداً منتشر نکنید مگر راه‌اندازی اولیه لازم باشد.
